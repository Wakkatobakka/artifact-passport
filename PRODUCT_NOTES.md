# Product Notes — What v0.7 Is Testing

## Hypothesis

An AI-native continuity pair can reduce project-orientation overhead by extracting what existing files already know, isolating current working state, preserving a compact decision/delta snapshot, routing a receiving AI to only the context it needs, and asking owners only for intent, authority, boundaries, and proof that files cannot establish.

v0.7 adds a second hypothesis: the reduction can be observed in a vendor-neutral way through fewer orientation actions, fewer unnecessary reads, less backtracking, fewer clarification loops, and shorter time to a usable project model—while maintaining equal or better answer quality. Host-reported token or credit usage is useful when available but is not required for the experiment.

## Why measurement is separate

Passport should not win an evaluation merely because an evaluator trusted it blindly or performed less verification. The Run Receipt is therefore separate from durable project truth, and the paired comparator applies a quality gate before efficiency numbers are interpreted cleanly.

The measurement layer is opt-in. Ordinary handoffs remain the same three-file sidecar bundle and do not collect invisible telemetry.

## First practical use

Use real preservation packages as matched A/B handoff tests. Give a fresh evaluator the same unfamiliar-project inspection prompt first without Passport and then with Passport. Preserve both receipts and compare them.

This directly tests the original pain: how much work does a new AI spend figuring out what the project is before it can safely help?

## Likely buyer pain

- Nobody knows which file is canonical.
- Generated output is edited directly and later overwritten.
- A vendor or AI adds a dependency that violates deployment constraints.
- Institutional knowledge leaves with the original builder.
- Important decisions exist only in old chat context.
- “It looks right” substitutes for acceptance testing.
- Documentation implies authority it cannot actually establish.
- AI repeatedly burns time/tokens rediscovering the same project structure.

## Commercial boundary

The file format should remain portable and inspectable. Potential paid value sits in:

- guided creation and validation;
- artifact-readiness and continuity audits;
- organization-specific profiles and policy checks;
- automated evidence collection;
- measured handoff reporting across repeated project transfers;
- integrations with document stores and development environments;
- managed handoff, migration, and continuity services.

## Do not build yet

- A cloud registry
- Cryptographic identity infrastructure
- Automatic command execution
- Hidden analytics or background telemetry
- Vendor-specific AI integrations
- A large ontology of artifact types
- A public standardization campaign

Those become rational only after repeated fresh-handoff tests demonstrate a real improvement.

## Signals to continue

- Fresh maintainers identify source, constraints, current state, and tests with materially fewer orientation actions.
- Passport runs open fewer irrelevant files while independently verifying at least as much.
- Clarification loops and backtracking fall across repeated matched trials.
- When hosts expose usage counters, measured input/total usage trends downward without quality loss.
- v0.6 `context_snapshot` fields prevent repeated rediscovery in multi-session maintenance.
- Multiple artifact types need the same core fields.
- Organizations recognize the failure mode without extensive explanation.
- AI systems consistently use the passport without confusing it for authority.

## Signals to stop or narrow

- Ordinary README files perform equally well under controlled testing.
- Passport reduces actions only by reducing verification quality.
- Owners will not maintain passports as artifacts change.
- Passports routinely become stale or contradict the package.
- Consumers treat descriptive procedures as permission to act.
- Benefits appear only in one specific AI host under custom prompting.
